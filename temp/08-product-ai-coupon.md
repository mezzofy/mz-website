**The merchant sets the walls**
- Maximum discount, by type
- Minimum spend to qualify
- How long each Pass is valid
- Monthly quota and daily cap
- Days and hours it can be used
- Which outlets accept it
- Whether it is running at all

**The AI picks inside them**
- The exact discount on each Pass
- When to release, and how many that day
- Which channel to place it in
- Which customers see it
- How to shift volume toward off-peak hours when allowed

> **What it learns from.** Redemption patterns across the exchange, time of day, location, category demand and the merchant's own history. What it never does is set the merchant's boundaries — those are typed in by a person.

## Two offer types to start

_Label: Percent off_

### 10% to 50%

Scales with the bill. The merchant sets a range; the AI picks a point inside it for each Pass. Suits variable basket sizes.

_Label: Amount off_

### $1 to $100

Fixed value per Pass. Minimum spend is required, and the system enforces a floor so a discount can never exceed a set share of the bill.

Product-specific offers arrive with POS integration, where the item data already lives. Tickets are never AI-generated: capacity is real and finite.

<!-- SECTION (plain) -->

## Guardrails, not guidelines

#### Hard ceilings

Quota, cap and depth are enforced in the system. The AI has no override.

#### Preview mode

New merchants approve the first campaigns before anything is issued. Automation follows trust.

#### Kill switch

Pause stops creation instantly. Passes already issued stay valid until expiry, because a customer paid for that guarantee.

## Free for the merchant, start to finish.

No creation, distribution or redemption fee. The customer pays a few cents for the guarantee, and that funds the exchange.
